# The Body Problem
<img width="1000" height="800" alt="image" src="three-body.gif"/>

## The Two-Body Problem
The two-body problem is a mathematical problem of how two bodies move over time, given their mass, current speed, and motion direction, assuming both objects move only by gravity. 

* **Core Question:** "What are the trajectories of two masses in space if the only force acting on them is their mutual attraction?"
* **Solution:** A closed-form solution is possible for two bodies by re-formulating it as two one-body problems. This allows for explicit expressions for the positions of both bodies over time by addressing the corresponding system of differential equations.

## The Three-Body Problem
The Three-Body Problem extends the two-body problem by adding a third mass and involves determining the motion or trajectory of three bodies, given their initial positions and velocities, in accordance with Newton's laws of motion.

* **Complexity:** Adding a third mass drastically increases the problem's complexity, generally leading to a chaotic, non-periodic system.
* **Solution:** Explicit solutions for the differential equations of the three-body problem do not exist. Consequently, the problem is typically tackled with numerical integration, which is computationally expensive and time-consuming. Solving this problem remains a significant challenge.

# Tasks

Your goal in this challenge is to learn how to predict the movement of the three bodies on a 2D plane given a set of initial positions, without using numerical solvers. At the initial positions, velocities are zero.

You will have access to a dataset from simulations of the 3-Body Problem under specific initial conditions. You can access position and velocity measurements for each body over several time steps. We denote the position of object 1 at a given time as $(x_1, y_1)$ and the velocity as $(v_{x_1}, v_{y_1})$.

## Task 1: Setting the Baseline
Establish a baseline model for comparison with any developments.

### Task 1.1 Data Preparation and Validation Pipeline
* Explore the training data for anomalies and visualize trajectories. Each trajectory consists of 258 lines. After a collision, all lines of that trajectory will be zero up to the 258th data point.
* Split the dataset into independent training, validation, and test sets (no shared initial positions between sets).
* Describe your validation strategy on the slides. You might need to code a new `train_test_split` function.

### Task 1.2 Learn the baseline model
* Learn a Linear Regression baseline model to predict the position of each of the 3 bodies at a given time $t$.
* Create a pipeline and add a `StandardScaler` instance before the regressor.
* Assess model quality using a y-y hat plot.
* Submit the baseline model to Kaggle as `baseline-model.csv`.
* Show plots and analysis in the slides, noting any large discrepancies between your local test split RMSE and Kaggle's RMSE. Update your validation strategy if necessary.

## Task 2: Nonlinear models on the data — the Polynomial model

### Task 2.1 Development
* Develop a function to validate a polynomial regression model: 
    `def validate_poly_regression(X_train, y_train, X_val, y_val, regressor=None, degrees=range(1,15), max_features=None)`
* The function should return the best model and the best RMSE.
* Sample a small percentage of training data for faster testing.
* Print the number of features generated by `PolynomialFeatures` (`n_output_features_`) and comment on this in the slides.
* For Kaggle submissions, train *only* with the best-performing degree to avoid feature complexity. Check `RidgeCV` and other regularization methods.
* Run the function ten times, plot the distribution of selected degrees on the slides, and select the best degree based on this analysis.

### Task 2.2 Evaluation
* Evaluate your nonlinear model against the baseline using RMSE and y-y hat plots. Comment on the results.
* Submit to Kaggle as `polynomial_submission.csv`.

### Task 3.3 Adding Variables

### Task 3.4 Evaluation of Variable Augmentation
